\section{Safe Contextual Banditへの拡張可能性（概念実証）}
\label{sec:phase2_concept}

本節では，Phase 2の問題設定と位置づけについて述べる．
Phase 1では，ルールベース方策によって固定間隔より低電力で運用可能な領域を示した．そこで本節では，Phase 1の実測データを用いたシミュレーションにより，Safe Contextual Banditへの拡張可能性の概念実証を行い，実機実装への接続点を整理する．
\noindent Phase 1との関係は次の通りである．

Phase 1で確立した$q_{\mathrm{event}}$（$\si{\micro\coulomb}/\text{event}$）と$P_{\mathrm{out}}(\tau)$の評価指標は，そのままSafe Contextual Banditの報酬関数と制約関数として利用できる．また，Phase 1のルールベース写像は，Warm-startの初期方策として活用可能である．

次に，Safe Contextual Banditの問題設定を示す．
\label{sec:safe_bandit_formulation}
\noindent 定式化について述べる．

Safe Contextual Banditは，コンテキスト$x$に応じて行動$a$を選択し，報酬$r(x,a)$を最大化しながら制約$g(x,a) \le \epsilon$を満たす問題として定式化される\scite{lattimore2020bandit}．

本研究では次のように定義する．
\begin{itemize}
  \item コンテキスト $x$: CCS（複合スコア）$\in [0,1]$
  \item 行動集合 $A$: アドバタイジング間隔 $\{500, 1000, 2000\}\,\si{\milli\second}$
  \item 報酬 $r(x,a)$: $-e_{\mathrm{event}}(a)$（負のエネルギー消費，最大化＝省電力化）
  \item 制約 $g(x,a)$: $P_{\mathrm{out}}(\tau \mid x,a) \le \epsilon$
  \item 許容遅延 $\tau$: \SI{1.0}{\second}
  \item 制約閾値 $\epsilon$: 0.10（10\%）
\end{itemize}

行動集合から\SI{100}{\milli\second}を除外した理由は，Phase 1の結果から\SI{500}{\milli\second}以上で主な省電力効果が得られることが確認されたためである．なお，将来的には\SI{100}{\milli\second}を含む4行動への拡張も可能である．
本節のシミュレーションでは，コンテキスト$x$を一定値に固定する．$r(x,a)$および$g(x,a)$は$x$に依存しない形に整理して扱う．以降は，この固定条件の下で$a$のみの関数として表記する．
\noindent Safe-UCBアルゴリズムを説明する．

Safe-UCB（Safe Upper Confidence Bound）は，各行動の報酬UCB値を計算しつつ，制約違反の信頼区間上界が$\epsilon$以下となる「安全行動集合」$S(x)$を動的に構築し，その中で報酬UCB最大の行動を選択する\scite{lattimore2020bandit}．

安全行動集合が空の場合は，フォールバック行動（本研究では最小間隔\SI{500}{\milli\second}）を選択する．これにより，未知環境においても制約違反を抑制しながら探索できる．

\subsection{Gate B/C：環境シフト・非定常診断による安全設計}
\label{sec:phase2_gatebc}
本小節では，環境シフト耐性の検証（Gate B）と非定常診断（Gate C）を通じて，Safety Filter + UCB（安全フィルタ付きUCB）の設計パラメータ（$w$, reset, $m$）を手順化する．ここでの数値は実機性能の主張ではなく，候補選定と設計判断の根拠である．なお，Gate Bは行動集合$A=\{500,1000,2000\}$，Gate Cは診断用に$A=\{100,500\}$を用いるため，条件は一致しない．

Gate Bでは，開始時の環境ずれ（warm shift）と途中切替（mid-run shift）を最悪ケースで統合し，切替後の累積違反に上限（cap=25）を設定したうえでパレートフロントから候補を抽出した．$m$を大きくすると切替後の違反は減るが，保守化によりコストは増える．詳細は\verb|results/phase2_offline_studies_2026-01-26_v05/gateb_pareto_cap25.md|に示す．

Gate Cでは，非定常での退化（\SI{100}{\milli\second}固定）を検出するため，スキャンデューティ比90\%$\to$70\%（行動集合$\{100,500\}$）で$m$を細かく変えて評価した．なお，本診断は退化検出を目的に$\tau=2.0$を用いる（仕様値ではない）．その結果，$m\ge 0.015$で\SI{100}{\milli\second}固定に退化し，$m=0.005/0.01$では\SI{500}{\milli\second}を維持しつつ必要時に短間隔へ退避する領域が確認された．詳細は\verb|results/phase2_gatec_sweep_m_2026-01-26_v02/sim_summary.csv|に示す．

Gate B/Cの共通可行領域において最小限の保守的設定として，初期設定は$w=0$, reset=1, $m=0.01$とする．一方で，安全寄りの感度分析として$m=0.02/0.03$を併記し，環境差やモデル誤差に備える．

考察を述べる．
\noindent Safe-UCBの有効性について述べる．

シミュレーション結果から，Safe-UCBは制約を守りながらOracleに近い報酬を達成できることが示された．これは，Phase 1のルールベース方策からの発展として，Safe Contextual Banditが有効であることを示唆する．
\noindent Warm-startの可能性について述べる．

Phase 1のFixed-CCS写像を初期方策として利用することで，探索初期の制約違反を抑制しつつ，より早く最適解へ収束できる可能性がある（Warm-start効果）．本シミュレーションではCold-startのみを実装したが，段階2ではWarm-start比較を追加予定である．
\noindent 制約モデルの限界について述べる．

本シミュレーションでは，制約モデル（$P_{\mathrm{out}}(\tau)$）に推定値を使用したため，実環境での制約違反率は異なる可能性がある．特に，E2環境（高干渉）では$P_{\mathrm{out}}(\tau)$が悪化するため，実測データに基づく制約モデルの構築が今後の課題である．
\noindent 実機実装への接続について述べる．

Phase 2の実機実装では，発見遅延（TL）のリアルタイム計測，制約違反時のフォールバック機構，オンライン学習によるモデル更新，および環境変化への適応性検証が必要となる．これらは，Phase 1で確立した計測系・ログ設計・指標定義の上に構築可能である．

最後に本節をまとめる．
本節では，Phase 1の実測データに基づくシミュレーションにより，Safe Contextual Banditへの拡張可能性の概念実証を行った．Safe-UCBは制約を守りながら報酬改善が可能であり，Phase 1のルールベース写像からの自然な発展経路となる．制約モデルの実測値取得と実機実装は今後の課題である．
