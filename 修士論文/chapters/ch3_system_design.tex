\section{問題設定とシステム設計}

まず，世界モデルについて述べる．
本研究はアプリケーション層と通信層を跨ぐクロスレイヤー制御を対象とし，情報の生成・観測位置が層ごとに異なることを前提として扱う．アプリケーション層はHARアプリ，通信層はBLEアドバタイジングを想定する．本節では，本研究で扱う構成要素をアクターとして整理し，設計の前提を明確にする．

\tabref{tab:actors}に，本研究で扱うアクターとその役割を示す．本研究では送信側のEdge Node，受信側のGateway，観測者のObserver，安全基準のSafety Oracle，および方策決定モジュールの5つのアクターを区別して扱う．

システム要件について述べる．

本研究の設計で重要となる要件は次の5点である．
\begin{itemize}
  \item 認識：HAR推論から確率分布を得て，不確実度$U$と安定度$S$を計算できること．
  \item 意思決定：$U,S$からCCSを構成し，アドバタイジング間隔$a$を決定できること．
  \item 通信：BLEアドバタイジングとして送信し，受信側の非理想スキャン下で到達できること．
  \item 安全性：QoS悪化の兆候がある場合に短間隔へ移行できること．
  \item 観測可能性：意思決定の根拠である$U,S,\mathrm{CCS}$，閾値，切替理由をログに残せること．
\end{itemize}

次に，主要評価指標と設計方針について述べる．
本研究では，評価軸を明確化するため，主要評価指標を定義する．\tabref{tab:kpi}に主要・補助評価指標を示す．主要評価指標は電荷消費の正規化指標$\si{\micro\coulomb}/\text{event}$，期限超過率$P_{\mathrm{out}}(\tau)$，遅延の95パーセンタイル$TL_{p95}$から構成され，「省電力」と「期限超過」の同時評価を実現する．補助評価指標は平均電力，PDR，RSSI，切替頻度等から構成され，要因分析のための補足指標として扱う．

また，設計方針として，拡張性を考慮したインターフェース設計を採用する．コンテキスト入力から間隔出力へ単純に写像する構造を保ち，ルールから学習へ差し替え可能にする．端末内比較では，受信端末と設定を固定し，OS依存の影響は端末内で相殺して解釈する．ログ優先では，評価指標算出に必要な列を必ず残し，派生値は後処理で再計算できる形にする．

続いて，目的関数と制約について述べる．
本研究の問題設定は，アドバタイジング間隔制御により電力，すなわち電荷消費を下げつつ，期限超過率を制約することである．動的制御の方策$\pi$に対し，期待電荷消費$\mathbb{E}[q_{\mathrm{event}}(\pi)]$を目的関数，期限超過率$P_{\mathrm{out}}(\tau;\pi)$を制約として
\begin{equation}
  \text{minimize}\quad \mathbb{E}[q_{\mathrm{event}}(\pi)]
  \quad \text{subject to}\quad P_{\mathrm{out}}(\tau;\pi)\le \epsilon
\end{equation}
と表せる．ここで$q_{\mathrm{event}}$の単位は$\si{\micro\coulomb}/\text{event}$であり，セッション中の電荷消費をイベント数で正規化した指標である．eventは真値系列の状態遷移イベントを指す．$\tau$は許容遅延，$\epsilon$は制約閾値である．定義は\secref{sec:metrics_detail}を参照する．コンテキストは$U,S$を基本とし，必要に応じてCCSを用いる．Phase 1ではルール$\pi_{\mathrm{rule}}$，Phase 2では学習$\pi_{\mathrm{safe\_mab}}$を想定する．

その後，フェイルセーフ機構について述べる．
非理想スキャン環境では，受信品質が瞬間的に悪化する可能性がある．このため，実装では安全側への移行として短間隔を選ぶ設計が望ましい．本研究では，切替規則の設計とログ化により，安全側に寄せた挙動を説明可能にする．
具体的には，通常はCCSに応じてアドバタイジング間隔を選択し，QoS悪化の兆候がある場合は短間隔へ移行できる設計とする．また，移行の根拠である切替理由をログに残し，監査可能にする．

最後にフェーズ設計としてPhase 1からPhase 2への移行を述べる．
Phase 1では，ルールベース方策で「計測・指標・実機実装」を成立させることを優先する．特に，TL/Poutの定義と時間同期，電力計測の健全化は，学習以前に必須である．Phase 2では，コンテキスト$U,S$と行動であるアドバタイジング間隔の選択をSafe Contextual Banditとして定式化し，環境差に適応しつつQoS制約を守る枠組みを検証する．
