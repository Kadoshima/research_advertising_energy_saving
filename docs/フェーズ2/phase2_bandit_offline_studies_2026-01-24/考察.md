### 0.1 Gate B（v04/v05）の Pareto と「次に試す候補」の絞り込み（cap付き）

v04 は Gate B を「抑え方込み」で比較できる状態にしたが、次に必要なのは **実機に持ち込む候補（m,w,reset）を短いリストにする**こと。
ここでは mean だけでなく p95（95パーセンタイル）も使い、序盤違反の worst-case 寄りを見て候補を絞る。

出典:
- 集計スクリプト: `scripts/phase2_offline_eval/analyze_gateb_pareto.py`
- v05 出力: `results/phase2_offline_studies_2026-01-26_v05/sim_summary.csv`
- v05 反復: `results/phase2_offline_studies_2026-01-26_v05/sim_replicates.csv`
- 出力（cap=25）:
  - `results/phase2_offline_studies_2026-01-26_v05/gateb_candidates_cap25.csv`
  - `results/phase2_offline_studies_2026-01-26_v05/gateb_pareto_front_cap25.csv`
  - `results/phase2_offline_studies_2026-01-26_v05/gateb_pareto_cap25.md`

定義（重要）:
- Gate B は 2 シナリオを統合する
  - shift at start: `E2_actions_500_1000_2000_warm_shift_from_E1`（resetは「未検知」扱い=0で評価）
  - mid-run shift: `E1_to_E2_actions_500_1000_2000_switch_mid`（resetは候補ごとに評価）
- worst-case は上の 2 シナリオで max を取る
- Pareto の y は `violations_first_after_switch_k` の worst p95（k=50）
- cap: `viol_after_worst_mean <= 25` を課し、長期違反が大きい候補（例: m=0）を事前に落とす

- (A) w=0, m=0.03, reset=1（安全寄り）

- (C) w=0, m=0.01, reset=1（省電力寄り）

### 0.2 Gate C（非定常: scan90 -> scan70）で shortlist を最小チェック

Gate C は「非定常っぽさに最低限追従できるか」を見る。現状の uccs_d4b は actions={100,500} のみで、tau=1.0 だと safe が 1 点に潰れやすいため、ここでは **追従性診断として tau=2.0** を用いる（仕様変更ではない）。

解釈:
- fixed/ucb/filter_ucb は 500ms に張り付き、shift後（scan70）に 500ms が微妙に unsafe（tau=2, epsilon=0.10）となるため violation_rate が 0.10 をわずかに超える。

## 1) 疑うべき前提: Safe-UCB が「学習」していない可能性

### 1.1 観測: Safe-UCB の違反率が「初期探索の違反」だけで説明できる

E2_fixed_v01 の Pout(1s) は 1000ms=0.111..., 2000ms=0.555...（出典: `results/phase2_offline_studies_2026-01-25_v02/tradeoff_table.csv`）。

Safe-UCB 実装は、最初に各腕を 1 回ずつ引く（出典: `scripts/phase2_offline_eval/models/safe_ucb.py`）。
このとき 1000/2000 を「各 1 回」引く期待違反回数は:

- 0.111... + 0.555... = 0.666...
- T=1000 で割ると 0.000666...

実測の `Safe-UCB` violation_rate_mean~0.00069 と整合する（出典: `results/phase2_offline_studies_2026-01-25_v02/sim_summary.csv`）。
つまり、**初期ラウンドロビン後はほぼ常に 500ms に張り付いている**（=探索していない）可能性が高い。

### 1.2 理由: 現行の safe_set 判定だと理論上「空になりやすい」

現状実装の safe_set 判定は以下（出典: `scripts/phase2_offline_eval/models/safe_ucb.py`）。

- constraint_ucb = mean_constraint + sqrt(2 log t / n)
- safe_set: constraint_ucb <= epsilon
- safe_set が空なら min(action)（フォールバック）

ここで epsilon=0.10、t=1000 とすると 2 log t ~ 13.8。
仮に mean_constraint=0（安全腕で違反が出ない）としても、

- sqrt(13.8 / n) <= 0.10 を満たす必要があり、n >= 1380 が必要

Horizon T=1000 では到達不能で、safe_set は空のままになりがちである。
この場合、Safe-UCB は「安全側へ退避するフォールバック装置」としては機能するが、**安全の中で最適化する学習器としては機能しにくい**。

結論:
- 現状の v02 は「Safe-UCB が強い」のではなく、「安全フォールバックが働いた」結果の可能性がある。
- このまま次へ進むと、Phase2 の学習導入が形骸化し、実機コンテキスト化で破綻しやすい。

## 2) 最短で効く修正（順番が重要）

方向性としては既存TODO（per-trial切替、action set統一、探索項std反映）も正しいが、順番を誤ると「張り付きで差が出ない」系の結果が増える。
最短で意味のある結論に到達するため、以下の順で進める。

### P0: まず「Safe bandit が学習できる土台」を作る（最優先）

#### 2.1 制約の上側CIを、epsilon=0.10でも現実的に収束する形へ変更

候補（実装コスト低）:

- (A) 時刻t依存をやめる（固定δの上側CI）
  - 例: Hoeffding: U_g = mean + sqrt( ln(1/δ) / (2n) )
  - δ は新規パラメータなので、凍結仕様（`docs/TODO.md`）と整合する根拠を示した上で決める（推測で固定しない）
- (B) Bernoulli 前提の上側区間（筋が良い）
  - Pout は確率なので、Clopper-Pearson または Beta posterior quantile が自然
  - 1000ms の safe/unsafe 反転（出典: `results/phase2_offline_studies_2026-01-25_v02/validity_constraint_e2_split.csv`）にも強い

対象コード:
- `scripts/phase2_offline_eval/models/safe_ucb.py`（safe_set 判定）
- （必要なら）`scripts/phase2_offline_eval/models/constraint_model.py`（confidence の定義）

#### 2.2 初期探索（round-robin）を「安全設計」に合わせて変更

医療/見守り寄りの文脈では「各腕を1回ずつ引く」が最初から安全要件違反になり得る。
実機へ繋ぐなら offline でも同じ作法に寄せる。

方針案:
- baseline safe arm（例: 500ms）だけで開始
- 他腕は「安全と言える条件（上側CI<=ε）」を満たしたら初めて探索
- 学習器の外側に安全フィルタ（Action Masking）を置く設計でも良い（後述）

対象コード:
- `scripts/phase2_offline_eval/models/safe_ucb.py`（初期挙動、選択制御）

#### 2.3 gate の証拠として診断指標を出す

「学習している」ことを gate として示すには、違反率だけでなく内部状態の診断が必要。

例:
- safe_set_empty_rate
- safe_set_size（平均/分布）
- 行動選択比率（burn-in後の最頻値、遷移）

対象コード:
- `scripts/phase2_offline_eval/run_offline_studies.py`（CSV列追加）

v03 で実装済み（出典: `results/phase2_offline_studies_2026-01-25_v03/sim_summary.csv`）。

### P1: 差が出るシナリオで Safe bandit の価値を証明する

E2(τ=1, ε=0.10) は safe が実質 500ms 1 点になりやすく、Safe-UCB の価値が「張り付き」になりやすい。
まず safe が複数ある環境で「安全の中で省電力最適」を gate にする。

- Gate A 用シナリオ（最優先）
  - env: E1_scan90_stress_v5
  - actions: {100,500,1000,2000}
  - reward: per_60s
  - constraint: tau=1.0, epsilon=0.10
  - 根拠: ε=0.10 なら 100/500/1000 が safe、2000 が unsafe になり得る（出典: `results/phase2_offline_studies_2026-01-25_v03/epsilon_tau_sensitivity.csv`）。

診断用（仕様変更ではなく健全性テスト）:
- E2 は tau=2.0 を許容すると safe が {500,1000} になり、Safe bandit の「選好」を観測しやすい（同出典）。

### P2: warm-start を「本当に危ない条件」でテストする

狙い:
- prior 環境では 1000ms が safe に見える
- target（E2）では 1000ms が ε を跨ぐ/境界付近（v02では mean=0.111...）
- warm-start で 1000ms を早期に選び、序盤違反が出る
- Safety Filter / 保守マージン / 初期探索で違反バーストを抑えられる

この「序盤違反の再現」ができると、Phase2 の説得力が一気に上がる（Gate B）。

補助:
- prior 側の制約ソースを per-trial に切替し、境界越え/誤判定が起きやすい状況を作る
  - 候補: `results/stress_fixed/scan90/stress_causal_real_summary_1211_stress_full_scan90_v5.csv`

## 3) 次にやるべき検証（gate）を3つに絞る

- シミュ途中で Pout テーブルを切替（env switch）などで「途中から条件が変わる」を作る

- safe_set_empty_rate が高止まりしない

## 4) 実機へ繋ぐ最小設計（提案）

Phase1 の実機知見（非理想スキャン環境）を踏まえると、bandit を「いきなり置き換え」で投入するのはリスクが高い。
最小で壊れにくい設計は二層構造。

- 外側: Safety Filter（Action Masking）
  - 絶対に選べない行動を落とす（安全境界の誤差があっても退避できる）
- 内側: bandit（UCB/TS/LinUCB 等）
  - 省電力最適化に集中（状態は O(K) で軽量）

メモ:
- Safe-UCB を「一発で全部やる」設計にこだわる理由が弱い場合、Safety Filter + 通常 bandit の方が説明が簡単で実機で壊れにくい可能性がある。

## 5) 報酬（reward_mode）についての結論

- per_adv（uJ/adv）は、間隔を伸ばして「広告回数を減らす」効果（省電力の本筋）を構造的に消しやすい。
- 主タスク（学習/評価）は per_time 系（per_60s 等）に統一し、per_adv は副用途（計測健全性チェック）へ格下げするのが最短。

## 7) 結論（Gate B/C の手続きで指摘に耐える形に収束）
- 目的: Gate B/C を手続きとして統合し、恣意性を抑えた。
- Gate B: warm/mid を worst-case 統合し、`viol_after_worst_mean <= 25` の cap を入れて Pareto 抽出した。w=0, reset=1 の m={0.03, 0.02, 0.01} が残り、m を上げるほど `viol_after_worst_mean` は低下し `cost_worst_mean` は増加する（`results/phase2_offline_studies_2026-01-26_v05/gateb_pareto_cap25.md`）。
- Gate C: scan90->scan70, actions={100,500}, tau=2.0 で m を細粒度 sweep し、m>=0.015 で 100ms 固定に退化することを確認した。m=0.005/0.01 は 500ms を維持しつつ退避する（`results/phase2_gatec_sweep_m_2026-01-26_v02/sim_summary.csv`）。
- 結論: Gate B/C の共通可行領域の最小保守性として w=0, reset=1, m=0.01 を暫定 default とし、m=0.02/0.03 を安全寄り感度分析として残す。
- 次の接続: 上記 default を実機の安全フィルタ初期値として持ち込み、シフト検知や行動集合拡張の評価へ移行する。
