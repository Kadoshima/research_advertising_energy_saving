## 1. 何ができるようになったか（結論）

- オフラインで Safe-UCB / UCB / Fixed-CCS / Oracle を比較し、制約違反率と省電力指標のトレードオフを再現可能にした。
- reward_mode を 2 種類（per_adv / per_60s）で切り替えられるようにし、報酬定義の違いで「差が出る/出ない」を確認可能にした。
- v01（per_adv）: Safe-UCB と UCB の差がほぼ出ない（報酬が短間隔寄りで、制約も満たしやすい構造）。
- v02（per_60s）: UCB が省電力側（長間隔）へ寄って制約を破り、Safe-UCB との差が明確に出る。
- v03: CI/初期探索のオプション化、`filter_ucb`（Safety Filter + UCB）追加、Gate A/B/C 用のシナリオ追加（safeが複数ある環境/環境シフト/非定常の最小診断）。
- v04: `filter_ucb_online`（オンライン更新の Safety Filter + UCB）を追加し、Gate B（環境シフト）を「抑え方込み」で比較可能にした。
- v05: Gate B の候補定義を「指摘に耐える形」にするため、(1) viol_after の cap を導入し、(2) Gate C で m を細粒度に sweep、(3) その候補を Gate B に戻して再評価できる導線を整備した。

## 3. 仕様（問題設定と用語）

基本の仕様は `docs/フェーズ2/Phase2_MVP仕様書_2026-01-21.md` に準拠する。

- 行動 a: BLE advertising interval（ms）
- 制約 g(a): Pout(tau | a) = Pr[TL > tau]
- tau: 許容遅延（秒）
- epsilon: 許容違反率（Pout の上限）
- context: 本来は CCS（0..1）だが、現状の studies は context=0.5 固定（非コンテキストの最小構成）

本 studies のデフォルトは以下:
- tau=1.0, epsilon=0.10（出典: `docs/フェーズ2/Phase2_MVP仕様書_2026-01-21.md`）
- T=1000, n_reps=100, base_seed=0xD4B40201（出典: `scripts/phase2_offline_eval/run_offline_studies.py`）

## 5. 実装の現状（コード仕様）

### 5.1 報酬モデル（RewardModel）

実装: `scripts/phase2_offline_eval/models/reward_model.py`

対応 action（現状）:
- 100/500/1000/2000ms のみ（固定間隔）

reward_mode:
- per_adv:
  - cost(a) = muC(a) = (E_on(a) - E_off) / N_adv(a) [uJ/adv]
  - ここで E_on/E_off は stats の mean を使用し、N_adv は trials の adv_count の平均を使用する（簡易）。
  - sigma は「E_on の std を N_adv で割る」近似（v01 互換、E_off の分散は無視）。
- per_60s:
  - cost(a) = DeltaE_total(a) = (E_on(a) - E_off) [mJ/60s]
  - sigma は sqrt(std_on^2 + std_off^2) の近似（独立を仮定）。

備考:
- 報酬 r(a) は常に `-cost(a)`（最大化問題に合わせる）。
- cost は環境依存ではなく、deltae sweep の結果を全 env に流用している（現状は「差が出るか」の確認優先）。

参考（実測から導出された cost 値の一覧）:
- per_adv（例）: `results/phase2_offline_studies_2026-01-24_v01/tradeoff_table.csv`
  - action=500 で mu_c_uJ_event=12623.724..., action=1000 で 17922.065..., action=2000 で 34681.580...（E2_fixed_v01 行）
- per_60s（例）: `results/phase2_offline_studies_2026-01-25_v02/tradeoff_table.csv`
  - action=500 で cost_mean=1514.846..., action=1000 で 1093.245..., action=2000 で 1075.129...（E2_fixed_v01 行）

### 5.2 制約モデル（ConstraintModel）

実装: `scripts/phase2_offline_eval/models/constraint_model.py`

サポート:
- tau は 1.0/2.0/3.0 を想定（pout_1s/pout_2s/pout_3s、または TL サンプルから算出）
- action は原則 100/500/1000/2000ms を想定（RX ログからは推定間隔を最近傍へ丸める）

表 CSV の読み込み:
- interval_ms が無ければ mode から抽出（正規表現: FIXED[_-](\\d+)）
- interval_ms ごとに pout_* を集約し、Pout の mean/std/n を保持

RX ログの読み込み（E2 fixed sweep 用）:
- RX/*.csv の ms と mfd を読む。
- mfd から seq を 16 進で復元し、seq ごとの最初の受信時刻（ms）を集める。
- (seq, ms) の傾きから advertising interval を推定し、100/500/1000/2000 に最近傍マップする（20% 以上ずれる場合は dynamic とみなして除外）。
- seq*interval - ms の中央値を offset として用い、時刻を補正する。
- event_period=60s として「60s ごとの仮想イベント時刻」を置き、次に到達した RX を探して TL を作り、Pout(tau)=Pr[TL>tau] を試行ごとに算出する。
- この per-trial Pout を保持しているため、E2 の split 妥当性チェックが可能（`validity_constraint_e2_split.csv`）。

### 5.3 アルゴリズム（Safe-UCB / UCB / Fixed-CCS / Oracle）

実装: `scripts/phase2_offline_eval/models/safe_ucb.py`

共通:
- 最初は各 action を 1 回ずつ引く（ラウンドロビン）。
- 以降は empirical mean と探索項で選ぶ。

Safe-UCB（実装版）:
- 報酬 UCB: mean_reward + sqrt(2*log(t)/n)
- 制約 UCB: mean_constraint + sqrt(2*log(t)/n)
- safe_set: constraint_ucb <= epsilon の action
- safe_set が空なら min(action) にフォールバック

注意:
- MVP 仕様書（`docs/フェーズ2/Phase2_MVP仕様書_2026-01-21.md`）の擬似コードと異なり、現実装は reward/std を探索項に掛けていない（今後の調整余地）。

Fixed-CCS:
- context=0.5 固定だと、theta_low=0.40 < 0.5 < theta_high=0.70 のため「中間腕」を選ぶ。
- actions={500,1000,2000} では 1000ms、actions={100,500} では 500ms を選びやすい。

Oracle:
- constraint_model.predict(a) <= epsilon を満たす action の中から reward_model.mean(a) が最大（=cost が最小）を選ぶ。
- safe が空なら min(action) にフォールバック。

## 7. 結果（v01 と v02 を並べて読む）

### 7.1 tradeoff（コストと Pout）

v01（per_adv）では、muC（uJ/adv）は短間隔が有利に見える。
- E2_fixed_v01 の例（出典: `results/phase2_offline_studies_2026-01-24_v01/tradeoff_table.csv`）
  - 500ms: mu_c_uJ_event=12623.724..., pout_1s=0.0
  - 1000ms: mu_c_uJ_event=17922.065..., pout_1s=0.111111...
  - 2000ms: mu_c_uJ_event=34681.580..., pout_1s=0.555555...

v02（per_60s）では、DeltaE_total（mJ/60s）は長間隔が有利に見える。
- E2_fixed_v01 の例（出典: `results/phase2_offline_studies_2026-01-25_v02/tradeoff_table.csv`）
  - 500ms: cost_mean=1514.846..., pout_1s=0.0
  - 1000ms: cost_mean=1093.245..., pout_1s=0.111111...
  - 2000ms: cost_mean=1075.129..., pout_1s=0.555555...

単位の読み方:
- v01 の avg_energy_uJ_event は「1 ステップ当たりの期待コスト」を uJ/adv で表したもの（reward が -muC のため）。
- v02 の avg_cost は「1 ステップ当たりの期待コスト」を mJ/60s で表したもの（reward が -DeltaE_total のため）。
- どちらも 1 ステップが何秒に対応するかは studies 側では固定していない（現状は bandit の挙動比較が主目的）。

### 7.2 v01（per_adv）の主結果

出典: `results/phase2_offline_studies_2026-01-24_v01/sim_summary.csv`

- E2_actions_500_1000_2000_cold:
  - Safe-UCB: violation_rate_mean=0.00069
  - UCB: violation_rate_mean=0.00071
  - Fixed-CCS: violation_rate_mean=0.11279
  - Oracle: violation_rate_mean=0

解釈:
- 行動集合が {500,1000,2000} で、報酬も制約も 500ms 側に寄る構造になりやすい。
- そのため Safe-UCB と UCB の差は「初期探索で危険腕を何回引くか」に縮む。

### 7.3 v02（per_60s）の主結果

出典: `results/phase2_offline_studies_2026-01-25_v02/sim_summary.csv`

E2（actions={500,1000,2000}, cold）:
- Safe-UCB: avg_cost_mean=1514.527..., violation_rate_mean=0.00069
- UCB: avg_cost_mean=1078.802..., violation_rate_mean=0.48156
- Fixed-CCS: avg_cost_mean=1093.570..., violation_rate_mean=0.11279
- Oracle: avg_cost_mean=1515.399..., violation_rate_mean=0

scan70（actions={100,500}, cold）:
- Safe-UCB: avg_cost_mean=3366.661..., violation_rate_mean=0.02537
- UCB: avg_cost_mean=1517.498..., violation_rate_mean=0.22855
- Fixed-CCS: avg_cost_mean=1515.399..., violation_rate_mean=0.22878
- Oracle: avg_cost_mean=3368.598..., violation_rate_mean=0.0251

解釈:
- per_60s にすると「長間隔=低コスト」が効くため、UCB は安全制約を無視して長間隔へ寄りやすい。
- Safe-UCB は safe_set（constraint_ucb<=epsilon）に制限されるため、E2 では 500ms に張り付き、scan70 では 100ms に張り付く。
- これにより「省電力 vs QoS（制約）」のトレードオフが数値として見える。

### 7.4 split 妥当性（v02）

### 7.6 v04（Gate B: 抑え方込みで比較, filter_ucb_online）

出典: `results/phase2_offline_studies_2026-01-26_v04/sim_summary.csv`

v04 では、`filter_ucb`（固定マスク）に対して、**オンライン観測でマスクを更新する** `filter_ucb_online` を追加した。
目的は Gate B（環境シフト時の序盤違反）を「抑え方込み」で比較し、実機へ持ち込む設計判断の材料にすることである。

実装メモ（重要）:
- warm-start で prior と target が異なる場合、`switch_at=0` として「全区間=after switch」扱いにし、`violations_first_after_switch_k`（デフォルト k=50）が常に定義されるようにした。
- `filter_ucb_online` は、prior 環境から作った allow-list を起点にしつつ、オンラインの制約推定で unsafe になった行動をマスクする（min(action) を常にフォールバックとして残す）。

## 9. 現状の限界と注意点（実験設計上のリスク）

- 報酬モデルは deltae sweep の結果を全 env に流用している（環境依存を持たない）。
- 制約モデルは固定間隔の Pout を中心に扱い、動的方策の依存構造（切替直後の挙動など）を表現していない。
- シミュレーションは i.i.d.（独立同分布）近似で、連続欠落などの時系列相関を持たない。
- regret_vs_oracle は「Oracle（制約を守る上界）」基準なので、制約を破る UCB は負の regret になり得る。
