                         論   文   要   旨



  本研究では，人間活動認識（Human Activity Recognition: HAR）の推論不確実度に基
づいて Bluetooth Low Energy（BLE）のアドバタイジング間隔を適応制御し，BLE アド
バタイジング通信における省電力化とサービス品質（Quality of Service: QoS）維持を両立
する手法を提案し，その有効性を評価した．ウェアラブル端末やエッジデバイスでは，常時
通信による電力消費が課題となる一方，スマートフォン側のスキャンは OS 等の制約により
受信特性が変動しやすく，アドバタイジング間隔を単純に長くすると受信遅延や期限超過が
増える．
  提案手法では， HAR の出力確率から得られる不確実度と時間的安定度から複合スコア
（Composite Confidence Score: CCS）を構成し，その値に応じてアドバタイジング間隔を
段階的に切り替えるルールベース方策を定義した．評価のために，送信（TX）・電力ロガ
（TXSD）・受信（RX）の三ノード構成を用いた計測システムを構築し，省電力指標 qevent
（µC/event）と受信遅延に基づく期限超過率 Pout (τ ) を同一試行で評価できるようにした．
  オフライン評価と実機実験により，単純な閾値ルールでも固定間隔より低電力で運用可能
なパラメータ設定（運用点）が存在することを確認した．さらに，100 ms と 500 ms の 2 値
切替を用いた最小構成の動的制御を実装し，電力と QoS のトレードオフにおいて中間的な
特性を示すことを確認した．受信条件を悪化させた条件（scan70，scan duty を 70% に低
下）では，固定 500 ms の Pout (1s) が 0.285 まで悪化する一方，方策は 0.089 に抑え，固
定 100 ms より平均電力を約 3.7% 低減した．最後に，非理想スキャン環境における限界と，
Safe Contextual Bandit によるオンライン最適化への拡張方針を議論した．
  加えて，U の時系列構造を乱す U-shuffle と，CCS を無効化する CCS-off のアブレーショ
ンにより，U が短間隔滞在量（電力）を，CCS が同電力で QoS（期限超過率・遅延）を改
善する役割が分離される可能性を示した．

1.1 研究背景と社会的文脈
 ウェアラブル端末やエッジデバイスにおいて，推論結果を近傍のスマートフォンへ低遅延
に通知する仕組みは，見守りや労働安全など多くの応用で重要である．しかし，常時高頻度
に通信を行うと電力消費が増大し，小型バッテリでの長時間運用が困難となる．Bluetooth
Low Energy（BLE）のアドバタイジング（Advertising）は接続を前提としない軽量な近傍
通信手段として広く利用されているが，受信側（スマートフォン）のスキャン動作は OS や
端末状態に依存し，連続スキャンが保証されない．


1.2 課題設定と狙い
 本研究は，人間活動認識（Human Activity Recognition: HAR）における推論不確実度
を通信制御に活用し，サービス品質（Quality of Service: QoS）制約（一定時間以内に受信
されること）を満たしつつ BLE アドバタイジング通信の省電力化を図る枠組みを提案する．
推論不確実度と時間的安定度から複合スコア（Composite Confidence Score: CCS）を構成
し，その値に応じてアドバタイジング間隔を段階的に切り替えるルールベース方策を定義す
る．また，送信・受信・電力計測を統合した計測基盤を構築し，電力指標と QoS 指標を同一
試行で評価できるようにする．


1.3 問題意識：エッジ HAR の「推論」と「通信」のトレード
    オフ
 ウェアラブル端末やエッジデバイスは，慣性センサ等から人の状態を推定し，異常や重要
な変化を近傍のスマートフォンへ通知する用途で用いられる．このとき，アプリケーション
層では「推論完了後，可能な限り低遅延で通知を行いたい」という要求があり，通信層では
「常に高頻度に送ると電力が増える」というトレードオフが生じる．
 さらに，BLE アドバタイジングは送信側の制御が容易である反面，受信側（スマートフォ
ン）のスキャン挙動は OS や端末状態に依存し，連続スキャンが保証されない．したがって，
アドバタイジング間隔を固定して設計した場合，環境変化により「必要なときに届かない」
か「届くが電力を使いすぎる」状況が生じる可能性がある．
 本研究は，このトレードオフを緩和するために，アプリケーション層（HAR）で得られる
推論不確実度を通信制御に利用し，「推論確信度の高低」に応じて送信頻度を調整する枠組
みを提案する．




                                                       2
1.4 本研究の核となる主張
 本研究の核となる主張は，次のとおりである．

   HAR の推論不確実度に基づく BLE アドバタイジング間隔の適応制御において，単
   純な閾値ルールでも固定間隔と比較して同等の QoS 制約下で平均電力を低減できる
   運用点が存在することを実測で示し，将来の Safe Contextual Bandit 最適化の基盤
   を提供する．


1.5 研究課題：QoS 制約下での省電力化
 本研究の目的は，受信遅延に基づく QoS 制約を満たしつつ，電力消費を抑制することで
ある．代表的な QoS として，イベント発生後に最初に受信されるまでの遅延（TL）を用い，
期限 τ を超える確率を
                       Pout (τ ) = P (TL > τ )                 (1.1)

として定義する（詳細は 5.7.2 節）．このとき，アドバタイジング間隔 a の選択（固定また
は動的切替）を含む方策 π に対して，以下の形で整理できる．

          minimize E[qevent (π)] subject to Pout (τ ; π) ≤    (1.2)

ここで  は許容する期限超過率の上限であり，qevent（単位：µC/event）はセッション中の
電荷消費をイベント数で正規化した指標である．平均電力 P や ∆E/Nadv 等は従属指標と
して併用し，単位整合の確認や要因分析に用いる（5.7.2 節）．

 本研究の貢献を以下にまとめる．

  1. 推論不確実度 U と安定度 S から複合スコア CCS を構成し，それを用いてアドバタ
   イジング間隔を段階的に切り替えるルールベース方策を提案した．
          ・電力（TXSD）
  2. 送信（TX）       ・受信（RX）の三ノード構成と同期信号（SYNC/TICK）
     により，同一試行で電力と QoS（TL，Pout (τ )）を評価できる計測基盤を整備した．
  3. TL/Pout の算出において開始位相ずれが結果を歪める可能性があることを示し，定

  4. オフライン評価（mHealth 合成）により，固定間隔点と候補方策点のトレードオフ

2.1 背景
2.1.1   BLE アドバタイジングとスキャンの基礎
 Bluetooth Low Energy（BLE）のアドバタイジングは，接続を確立せずに情報をブロー
ドキャストでき，端末側の実装が容易である
 [1]．ただし，アドバタイジングは受信側のスキャン窓に依存して観測されるため，送信側
がどれだけ制御しても「確実に届く」とは限らない．本節では，アドバタイジングとスキャ
ンの基本要素を整理する．


アドバタイジングイベントと 3 チャネル
 アドバタイジングは，規格上のアドバタイジングチャネル（37/38/39）を用いて送信され
る．送信側は，アドバタイジング間隔を Tadv として，概ね Tadv ごとにアドバタイジング
イベントを発生させる．アドバタイジングイベントは複数チャネルに送信されるが，周波数
ホッピングや干渉により，受信側におけるパケット受信成功率は確率的に変動する．


スキャン間隔・ウィンドウとデューティ比
 受信側は，スキャン間隔 Tscan ごとに，スキャンウィンドウ dscan の間だけ受信機を有効
化する．スキャンのデューティ比 δ は

                               dscan
                          δ=                            (2.1)
                               Tscan

で定義できる．δ が小さいほど受信側は省電力になるが，アドバタイジングイベントとの重
なりが起きにくくなり，発見遅延が増える．


発見遅延（TL）の概念
 イベント発生後，最初にアドバタイジングが受信されるまでの遅延を TL（Time-to-first-
Receive）とする．TL は，アドバタイジング間隔とスキャン窓の相互作用（位相差）で分布
が決まるため，平均受信率だけでは QoS を十分に表現できない．本研究では，一次 KPI と
                       ，TL 分布の裾（T Lp95 ）
して省電力指標 qevent（µC/event）               ，および期限超過率 Pout (τ ) を
採用する．

2.1.2   非理想スキャン環境

 スマートフォンのスキャン挙動は，端末機種，OS バージョン，画面状態，省電力機構，お
よび他アプリの利用状況に依存して変化する．Android では，アプリケーションがスキャン
を要求しても，OS が内部的にスキャンの間欠実行やスロットリング（帯域制限）を行う可
能性がある
 [2]．このため，本研究ではスキャンを理想的な一定窓として仮定せず，「非理想で観測で
きない内部状態がある」前提で送信側の制御を議論する．


不感地帯（Blind Spot）
 アドバタイジング間隔とスキャン周期が高調波関係に近い場合，アドバタイジングイベン
トが系統的にスキャンウィンドウと重ならない状態が継続し，発見遅延が極端に悪化する領
域が生じ得る．このような領域は，平均的な受信率が同程度でも TL の裾を悪化させるた
め，Pout (τ ) により議論する必要がある．


Android のスキャンモードと前提条件
 Android の BLE ス キ ャ ン は， ア プ リ ケ ー シ ョ ン が 要 求 す る ス キ ャ ン モ ー ド （例：
LOW_LATENCY）だけで挙動が一意に定まるとは限らない
 [2]．画面状態や電源管理の影響により，アプリケーションが意図したとおりに連続スキャ
ンできない場合がある．したがって，本研究は「受信側スキャンは非理想である」前提で，
送信側が取り得る適応制御の範囲を議論する．


OS 側のスロットリングとオポチュニスティック・スキャン
 スマートフォン側では，複数アプリのスキャン要求を統合するような挙動や，バックグラ
ウンド制約に起因するスロットリングが生じ得る．これらはアプリケーション側から直接観
測・制御できないため，評価では端末内比較と運用条件の固定（スキャンモード，画面状態
等）が重要となる．


端末内比較による評価手法
 スキャン挙動が端末・OS 状態に依存する以上，異なる端末間の比較は外的要因が支配的
になりやすい．本研究は，固定条件と提案条件を同一端末・同一設定で取得し，同一パイプ
ラインで集計する端末内比較を基本とする．


2.1.3   スリープ制御の役割

 本研究の評価は，送信側の電力と受信側の QoS を同時に扱う．このとき，sleep（スリー
プ）制御の扱いは，受信側と送信側で意味が異なるため，整理が必要である．


                                                                   7
スキャナ側のスリープ（スキャンデューティの縮退）
  受信側の sleep は，スキャンデューティ比 δ の低下として観測される．これは OS の省
電力機構に起因し，アプリケーション側から直接制御できない場合が多い．スキャナ側の
sleep は，TL 分布の右裾を伸ばし，Pout (τ ) を悪化させる方向に作用する．


アドバタイザ側のスリープ（平均電力の低下）
  送信側（DUT）の sleep は， CPU や無線を低消費電力状態に移行させることで平均
電力を下げる．アドバタイジング間隔を長くすると無線イベント回数が減るだけでな
く， sleep 状態の滞在時間が増加するため，平均電力が低下しやすい．本研究の予備計測
（sleep_eval_scan90）では，固定 100 ms から固定 500 ms への変更で平均電力が大きく低
下する一方，500 ms 以上では改善幅が小さくなる傾向が確認されている（詳細は 5.3 節）．


アドバタイジングが支配的コストになりやすい理由
  アドバタイジングイベントは，無線送信に加えてスタック処理や割り込み等を伴うため，
完全なスタンバイ sleep より高コストになりやすい．そのため，アドバタイジング間隔の制
御は「通信頻度そのものの削減」と「sleep 時間の増加」という 2 つの経路で省電力に寄与
する．


2.1.4   不確実度 U ・安定度 S ・CCS の基礎

  端末内推論（HAR）は，クラス確率分布として出力を持つことが多い．この確率分布から
             「いまの推論がどの程度信頼できるか」を定量化できる．ただし，
不確実度 U を導出すると，
確率は瞬間的に変動するため，時間的一貫性を表す安定度 S も併用する設計が有効である．


CCS の設計思想
  複合スコア CCS は，確信度 (1 − U ) と安定度 S を組み合わせた指標であり，
                                              「確信度お
よび安定度が高いほど長いアドバタイジング間隔を選択する」という単調な解釈を与える．
この単調性は，ルールベース方策の説明容易性に寄与する．


感度分析の必要性
  CCS は係数（例：α）や窓長 W に依存するため，分布が変わると閾値による分類結果が
変動する．本研究では，Phase 1 では説明容易性を優先し，固定の係数でルールベース評価
を行う．係数感度や較正は，今後の課題として整理する（関連研究・TinyML 章を参照）．




                                                         8
2.1.5   まとめ

 本節では，BLE アドバタイジングとスキャンの基本要素，非理想スキャン，sleep の二面
性，および不確実度指標の位置づけを整理した．次節では，これらを踏まえて関連研究を整
理し，本研究の新規性と立脚点を明確化する．


2.2 関連研究
2.2.1   BLE アドバタイジング・近隣発見の最適化
 BLE アドバタイジングにおける主要設計パラメータは，アドバタイジング間隔，送信チャ
ネル数，送信電力等である．これらは到達性（受信率・遅延）と電力のトレードオフに直結
するため，固定値の最適化や，状況に応じた動的制御が検討されてきた．


MAB によるアドバタイジング間隔選択
 アドバタイジング間隔の動的制御は，混雑度推定や直近の受信状況に基づくルールとし
て実装されることが多い．また，未知・非定常な環境では，有限個の行動集合からオンライ
ンで運用点を学習する枠組みであるマルチアーム・バンディット（Multi-Armed Bandit:
MAB）も候補となる
 [3]．本研究は Phase 2 での拡張可能性を残しつつ，Phase 1 では学習の前段階として評価
指標および計測手法を確立することに注力する．


3 チャネル送信と電力
 BLE アドバタイジングはアドバタイジングチャネル（37/38/39）で送信されるため，チャ
ネル数や送信回数は到達性と電力に影響する．本研究は Phase 1 ではチャネルマスク等を固
定し，アドバタイジング間隔の効果と不確実度駆動制御の枠組みに焦点を当てる．


非学習型アプローチ（多重化等）
 学習を用いないアプローチとしては，複数の間隔や送信パターンを組み合わせ，不感地帯
（Blind Spot）の影響を平均化する設計も考えられる．ただし，受信側スキャンが非理想で
ある場合，無線側のパラメータだけで性能が決まらないため，アプリケーション層の状態
（遷移期／安定期）を併用した説明が必要となる．


2.2.2   遅延制約・停止確率（Outage Probability）解析

 近隣発見では，平均遅延だけでなく，期限超過率 Pout (τ ) や遅延分布の裾（例：T Lp95 ）
が重要である．スキャン窓のデューティ比が低い場合，平均受信率が一定でも遅延分布が右


                                                   9
に伸び，Pout (τ ) が支配的な評価軸になる．BLE アドバタイジングに基づく遅延サービス
の可能性と最適化についても検討されている
  [4]．
  理想化した周期モデルでは，アドバタイジングイベントとスキャン窓の相互作用から遅延
分布を解析できるが，実際のスマートフォンは OS の省電力機構によりスキャンが間欠実行
され，観測できない内部状態が存在する．したがって，本研究では解析モデルによる厳密導
出ではなく，実測ログに基づき Pout (τ ) と電力のトレードオフを描き，方策比較を端末内比
較として解釈する．


スキャンデューティ・スリープと停止確率の関係
  受信側の sleep は，スキャンデューティ比の縮退として現れ，TL 分布の裾を悪化させる
方向に作用する．対して送信側の sleep は，アドバタイジング間隔の延伸と組み合わせるこ
とで平均電力を下げる．この二面性を踏まえ，sleep は背景・装置・考察に分散して扱う必
要がある．


2.2.3    不確実度駆動の通信制御（クロスレイヤー）

  推論モデルが出力する確率分布は，不確実度として定量化できる．不確実度に基づいて
「重要度に応じた通信制御」や「確信度に基づくサンプリング頻度の調整」といった制御は，
エッジ AI における省電力化の代表的な戦略である．
  ただし，不確実度の定義や較正が不適切であると，確信が過大評価されて長間隔に偏り，
QoS 違反が増える危険がある．本研究では，確率較正の必要性を踏まえつつ（将来課題），
まずは確率分布から導出した U と時間的一貫性 S を組み合わせ，説明可能な複合スコア
CCS として通信制御へ接続する．


2.2.4    TinyML 環境における制約付き学習および実装
  MCU 上で学習・制御を実装する場合，RAM や演算資源の制約により，実装可能なアル
ゴリズムが制限される．現実的には，学習器は単純な最適化を行い，外部に安全フィルタ
（Safety Filter: Action Masking 等）を置いてハード制約を担保する構造が採られることが
多い．
  本研究の行動集合（アドバタイジング間隔）は小さいため，Phase 2 での拡張としては，
低次元のコンテキストに対する軽量な Contextual Bandit が候補となる．一方，Phase 1 の
段階では，実験計測と指標定義がボトルネックになるため，まずはルールベース方策で再現
性の高いデータを取得することが重要である．

3.2 HAR 推論部（TinyML）と不確実度の構成
3.2.1   目的

 本研究の制御は，HAR の推論結果そのものではなく，
                          「推論がどの程度信頼できるか」を
表す不確実度と，「状態がどの程度安定しているか」を表す安定度に基づいて動作する．本
節では，TinyML 環境を想定した HAR 推論部の位置づけと現状を整理し，端末内推論から
不確実度 U と安定度 S を得て複合スコア CCS を構成する流れ，および実装上の制約と未
完タスクをまとめる．


3.2.2   HAR モデルと現状
 HAR は，加速度等の時系列入力を一定窓で切り出し，クラス確率分布を出力する．本研
究では参照モデル（A0）と小型モデル（A_tiny）を区別し，Phase 1 では評価指標・計測
系・制御の成立を優先するため，最終的な TinyML 最適化（A_tiny の性能到達や TFLite
整合の監査）は Phase 2 に跨る将来課題として位置づける．


3.2.3   不確実度 U

 HAR モデルは，各時刻 t においてクラス確率分布 p(t) = (p1 (t), . . . , pK (t)) を出力
する．本研究では，この確率分布から不確実度 U (t) を算出し，通信制御の入力情報（コン
テキスト）として利用する．不確実度 U は，正規化エントロピーとして定義できる

ここで U = 0 は確信度が高い（不確実性が低い）状態，U = 1 は不確実性が高い状態に

較正（Calibration）の位置づけ
 ソフトマックス確率は，ニューラルネットの過信（overconfidence）により，確率値が実
際の正解率を過大評価する場合がある．不確実度 U を通信制御に用いる場合，この過信は
「本来短間隔にすべき局面で長間隔を選ぶ」リスクに直結する．そのため，推論結果の確率
較正（例：温度スケーリング）により，U と実際の誤り確率の整合性を向上させることが望
ましい
 [6]．


3.2.4   安定度 S

 安定度 S は，直近窓におけるラベル遷移回数や，状態滞在時間に基づいて構成する．例え
ば，ラベル遷移が少ないほど安定であるという設計意図のもと，S を 1 に近づける．


窓長と応答性
 安定度は窓長 W に依存する．W が短いと遷移への応答が速い反面，ノイズに敏感にな
る．W が長いと安定する反面，過渡期に追従しにくい．本研究では，実装の単純性を優先
し，スライディング窓に基づく遷移回数の正規化という形で S を構成する（第 2 章）．


3.2.5   複合スコア CCS

 複合スコア CCS は，確信度 (1 − U ) と安定度 S の線形結合として定義する．


                CCS(t) = α (1 − U (t)) + (1 − α) S(t)      (3.3)

係数 α は設計パラメータであり，Phase 1 では説明容易性を優先して固定値（例：α = 0.7）
を採用する．ただし，α や窓長 W が変わると CCS 分布が変化し，閾値の意味が変わるた
め，モデル更新時には閾値の再調整（キャリブレーション）が必要となる．

係数設計と解釈

性（安定度 S ）を重視し，短時間の確信度の揺らぎで切替が発生しにくくなる．本研究では，
Phase 1 の主張（説明容易性）を優先し，確信度を主成分として扱う．


3.2.6   時系列生成とログ

 制御に用いる U (t)，S(t)，CCS(t) は，スライディング窓で逐次計算し，TX ログとし
て保存する．このログは，オフライン評価および実機評価で共通に利用するため，ログ形式
と時間軸の整合が重要である．
 本研究の想定はバッテリ駆動の小型端末であり，推論・制御・ログの計算コストは制約と
なる．不確実度 U は推論出力から 1 回で計算できるため，多回推論を要する不確実度推定
より計算コストが小さい．ただし，量子化や確率較正により U と閾値の意味づけが変化し
得るため，モデル更新時は閾値の再調整（キャリブレーション）が必要となる．

 本節では，TinyML 環境を想定した HAR 推論部の現状と，不確実度 U ・安定度 S・CCS
の構成を整理した．また，量子化と TFLite 整合の重要性，および未完タスクを明示した．
以降の章では，このコンテキストに基づくアドバタイジング間隔制御と，計測・指標に基づ

3.3 提案手法：CCS に基づく BLE アドバタイジング間隔制御
3.3.1   問題設定

 本研究は，アドバタイジング間隔 a を選択する方策 π に対して，電荷指標 qevent を小さ
くしつつ，受信遅延に基づく期限超過率 Pout (τ ) を制約する問題として整理する（問題設定
は 4.1 節と 5.7.2 節に従う）．


3.3.2   不確実度と安定度

 HAR モデルの出力確率分布から不確実度 U ∈ [0, 1] を算出し，過去一定窓におけるラ
ベル遷移回数から安定度 S ∈ [0, 1] を算出する（算出方法と前提は 3.2 節）．

値に応じてアドバタイジング間隔を段階的に切り替える．実装の単純性と説明容易性を優先

ヒステリシスと最小滞在時間
 CCS は推論誤差やセンサノイズにより変動するため，単純な閾値写像では切替が過度に

切替ロジック
 実装は，現在の間隔 at と CCS の観測値 CCSt から次の間隔 at+1 を決定する有限状態機
械として表せる．本研究では以下を満たす設計とする．

   • 単調性：CCS が高いほど長いアドバタイジング間隔が選択されやすくなる．
   • 安全側への移行：QoS 悪化の兆候がある場合は短間隔へ戻す余地を残す．
   • 振動抑制：ヒステリシスと最小滞在時間で切替頻度を抑える．

切替規則の例は，実験装置・計測方式（4.1 節）および実験設計（5.6.1 節）で示す条件（閾
値，滞在時間）と併せて具体化する．

3.3.4   ログと説明可能性（Observability）

 動的制御の評価では，「なぜその間隔を選んだか」を後から説明できることが重要である．
特に，本研究は非理想スキャンを前提とするため，受信品質の変動をすべて送信側のせいに
できない．したがって，意思決定プロセス（U, S, CCS）と使用したパラメータ（閾値，ヒ
ステリシス，最小滞在時間等）をログとして保存し，トレーサビリティ（追跡可能性）を確
保する．


切替理由（Reason）の記録
 切替のたびに，閾値越え，ヒステリシス判定，最小滞在時間による抑制，フェイルセーフ
移行などの理由を reason として記録する．これにより，結果図表の背後にある「切替の根
拠」を監査できる．


TX/RX/電力ログのスキーマ
 TX ログは方策の内側（U, S, CCS と選択した a），RX ログは受信時刻と seq，TXSD ロ

従って運用条件（端末，スキャン設定，sleep の有無）を固定する．


3.3.5   動的切替の最小構成（2 値制御）

 実機実験の初期段階では，電力低下の主効果が短間隔滞在の削減にあることを踏まえ，ア
ドバタイジング間隔を 100 ms と 500 ms の 2 値に限定した動的切替を用いる．この最小構
成により，計測系の同期とログ整合を保ちつつ，動的切替が期待通りに動作することを確認
する．


2 値制御の目的
 2 値制御は，行動空間を小さくすることで，実装・解析の複雑性を抑える目的がある．ま
た，100 ms と 500 ms の差は平均電力の主効果になりやすく，省電力化の寄与を説明しや
すい．

5.1.1   目的

 本節では，ストレス固定（stress_fixed）実験を用いて，QoS 指標（TL および Pout (τ )）
の定義を「論文で説明できる形」に固定し，実測結果を再現可能に整理する．特に，受信ロ
グの時間軸と真値（truth）の開始位相ずれが TL/Pout に与える影響を明確化し，補正手順
を定式化する．


5.1.2   実験条件の概要

 ストレス固定実験では，既知のラベル系列（truth）を TX 側で再生し，受信側（RX）が
それをどの程度の遅延で観測できるかを測定する．主な比較軸は以下である．

   • 受信設定：scan50（duty 50% 相当）と scan90（duty 90% 相当）
   • 固定アドバタイジング間隔：100 ms，500 ms，1000 ms，2000 ms
   • ストレス列：代表的な 2 条件（例：S1，S4）を中心に評価

各 trial について，TXSD ログと RX ログを対応付け，PDR，TL，Pout (τ )，平均電力など
を出力する．


5.1.3   v4 で観察された問題
 scan90 の v4 集計では，固定 2000 ms において Pout (1 s) が理論下限より小さく見える
等，理論的予測と整合しない挙動が観察された．原因は，RX ログの ‘ms‘と truth の時間軸
が一致している前提で TL/Pout を計算していた点にある．実機では試行開始のタイミング
がずれ得るため，この時間誤差を補正しない場合，TL/Pout が過小評価される．




                                                        31
5.1.4   定数オフセット補正による時間同期手法（v5）

 v5 では，TL/Pout 算出前に定数オフセットを推定し，RX ログの時刻を補正する．アド
               ，受信ログから得られる seq の初回観測時刻を first_ms(seq)
バタイジング間隔を ∆t（ms）
とすると，seq に対応する期待時刻は seq · ∆t である．複数の seq に対し，

           offset_ms = medianseq>0 (seq · ∆t − first_ms(seq))   (5.1)

としてオフセットを推定し，補正後の時刻を ms_aligned = ms + offset_ms とする．
TL/Pout は ms_aligned に基づいて算出する．この補正により，非同期な開始タイミング
（開始位相）に起因する過小評価を抑制できる．


5.1.5   生成物と再現性

 v5 では，per-trial の集計に加え，modes/agg/enriched の集約表を再現可能に生成する
パイプラインを整備した．また，scan50 と scan90 の比較結果も同一の定義で出力し，受信
設定の違いが PDR や TL/Pout に与える影響を整理できるようにした．


PDR の扱い
 PDR は受信ログの行数に基づく指標（重複含む）と，seq でユニーク化した指標（重複除
外）の 2 種類を区別する．QoS 比較では，アドバタイジングイベントの「何割を一度でも拾
えたか」を表す PDR_unique を優先する（5.7.2 節）．


有効データ長（Effective Length）と終端処理
 真値（truth）は有限長のラベル系列であり，試行時間のクランプにより末端の遷移が試
行区間外に出る場合がある．その場合，末端遷移を含めた評価は不安定になるため，truth
側も同じ長さにクリップし，イベント数 Nevent の分母を揃える．この処理は，試行間比較
と再現性の観点で重要である．

Phase 1 との関係

5.4.2   問題設定：Safe Contextual Bandit

定式化
 Safe Contextual Bandit は，コンテキスト x に応じて行動 a を選択し，報酬 r(a) を最
大化しながら制約 g(x, a) ≤  を満たす問題として定式化される
 [3]．
 本研究では以下のように定義する：

   • コンテキスト x: CCS（複合スコア）∈ [0, 1]
   • 行動集合 A: アドバタイジング間隔 {500, 1000, 2000} ms
   • 報酬 r(a): −eevent (a)（負のエネルギー消費，最大化＝省電力化）
   • 制約 g(x, a): Pout (τ | x, a) ≤ 
   • 許容遅延 τ : 1.0 s
   • 制約閾値 : 0.10（10%）

 行動集合から 100 ms を除外したのは，Phase 1 の結果から 500 ms 以上で主な省電力効果
が得られることが確認されたためである．将来的には 100 ms を含む 4 行動への拡張も可能
である．

6.1 非理想スキャン環境における解釈
 受信側スキャンの非理想性は，平均的な受信率だけでなく，遅延の裾や期限超過に影響す
る．端末・OS 状態に依存する要素を前提として，評価は各制御方針の優劣を相対的に評価
する必要がある．


6.1.1   評価の前提

 本研究では，端末内比較の前提を守るため，固定条件と提案条件を同一実験系で取得し，
同じ処理パイプラインで集計する．また，ログ欠損や同期ずれが評価結果に直結するため，
解析対象の選別や単位整合の確認を行う．


6.2 制御設計の妥当性と限界
 ルールベース方策は実装が単純であり，安全側のフォールバックを設計しやすい．ただ
し，環境ごとに最適な運用点は変化するため，固定閾値では追従できない場合がある．さら
に，切替頻度の増加はログ整合や同期の難易度を上げるため，実装面での制約もある．


6.2.1   2 値制御の位置づけ
 2 値制御は，実機検証を最小構成で成立させる上で有効である．ただし， 1000 ms や
2000 ms など長間隔を含めた最適化は，より大きな省電力の可能性を持つ．今後は，計測・
同期の堅牢性を維持した上で行動空間を拡張し，QoS 制約の境界をより広い範囲で評価する
必要がある．


6.2.2   閾値設計と感度

 CCS 閾値は，入力データ（活動種別やモデルの確信度分布）に依存する．閾値を厳しくし
すぎると短間隔に偏って省電力効果が薄れ，緩くしすぎると長間隔に偏って QoS 違反が増
える．したがって，オフライン評価で候補を絞り込んだ上で，実機の端末内比較で境界付近
で詳細な評価を行うアプローチが実務上有効である．


6.2.3   U と CCS の役割分離（実機アブレーション）
 本研究では， 2 値制御の実機成立（D2b）に加え，受信条件悪化時の頑健性（D3）と，
U/CCS の役割分離（D4/D4B）を追加検証した．D4（U-shuffle）では，制御器の構造を固
定したまま U の時系列構造を乱すと短間隔に固定される形で崩れ，省電力効果が失われる
ことを示した（5.3.3 節）．対して D4B（CCS-off）では，平均電力（=短間隔滞在量）をほ

                                                 67
ぼ同一に保ったまま，CCS 有効化により Pout (1s) と TL が改善することを示した（5.3.3
節）                        」を，CCS が「いつ短間隔を使う
 ．これらより，U が「どれだけ短間隔を使うか（電力）

6.3 省電力（スリープ）機能に関する考察と評価の公平性
 本研究は，アドバタイジング間隔を制御することで無線イベント回数を減らし，さらに送
信側が sleep に入れる時間を増やすことで平均電力を下げることを狙う．ただし，sleep は計
測条件そのものでもあるため，条件が混ざると比較が成立しない．本節では，sleep を議論
に入れるための前提を整理する．


6.3.1   送信側スリープ（平均電力への寄与）

 送信側（DUT）が light sleep 等に入る構成では，アドバタイジング間隔を延ばすほど
sleep 時間が増え，平均電力が低下しやすい．ただし，周辺回路やロギングの定常負荷が支
配的な場合，改善は飽和する．したがって，sleep の有無（ON/OFF を含む）を条件として
明示し，同一コード系列・同一設定の端末内比較として評価することが必要である．


6.3.2   受信側スリープ（スキャンデューティの縮退）

 受信側（スマートフォン）のスキャンは，OS の省電力機構や端末状態により間欠化し得
る．この受信側 sleep は，TL 分布の裾を伸ばし，Pout (τ ) を悪化させる方向に作用する．し
たがって，本研究の主張は「理想スキャン下の最適性」ではなく，「非理想スキャン下でも
端末内比較として省電力な運用点が存在し得る」ことに置く．


6.3.3   OFF 計測と差分評価
 計測系の定常負荷が大きい場合，平均電力だけではアドバタイジング間隔の差が埋もれ
る．この場合，アドバタイジング ON/OFF 差分 ∆E をアドバタイジング回数で正規化した
∆E/Nadv を併用することで，「無線 1 回当たりの増分」として議論できる．ただし，OFF
の sleep 状態やスタック状態が ON と異なると差分の解釈が難しくなるため，Runbook に
従って条件を固定する必要がある．


6.4 Safe Contextual Bandit への拡張
 将来的には，コンテキスト（不確実度，安定度）に応じて行動（アドバタイジング間隔）を
選択し，報酬（省電力）を最大化しながら制約（Pout (τ ) ≤ ）を満たす Safe Contextual


                                                      68
Bandit として定式化する．ルールベース方策と固定間隔の基準データは，Warm-start の事
前情報として活用できる．


6.4.1    Warm-start の意義
 オンライン学習では，学習初期の探索によって QoS 制約を破るリスクがある．ルールベー
ス方策は，安全側の初期方策として利用でき，探索の範囲を制約内に保つ設計に接続しやす
い．したがって，Phase 1 に相当するルールベース評価は，オンライン最適化の前提条件と
して重要である．


6.5 本研究における課題と今後の展望
 本研究は，Phase 1 として評価系を確立することを目的に置くため，未完点を将来課題と
して整理し，Phase 2 へ接続する材料とする．


6.5.1    HAR モデル（A_tiny）の未完点
 A_tiny は，4 クラス性能の未達や TFLite 生成・実機計測が未完である．この状態で閾
値制御を議論すると，確率出力の較正や量子化誤差により，CCS 分布と閾値の意味が変化
する危険がある．したがって，本論文では参照モデル A0 を土台として不確実度定義を固定
し，A_tiny の改善は今後の課題として明確化する．


6.5.2    計測系トラブルの位置づけ

 計測系のトラブル（SYNC 取りこぼし，UART 欠損，SD 失敗など）は，研究の本質では
ないが，無視すると結論を逆転させ得る．そのため，本研究では計測系の不具合要因と対策
を 4.2 節で整理し，評価の前提として本文に明示した．


6.6 本研究の妥当性に対する脅威（Threats to Validity）
 本研究の評価は，実機の端末内比較と，オフライン合成評価を組み合わせている．した
がって，以下の脅威と限界を明示する必要がある．

   • 外的妥当性：受信端末や OS バージョンが変わると，スキャンの非理想性が変化し，
        同一方策でも QoS が変化し得る．
   • 内的妥当性：ログ欠損や単位換算の誤りは結論を逆転させ得るため，計測健全化と整
        合性確認を必須とする（4.2 節）．
   • 統計的妥当性：実機評価には各条件 n = 3 で評価した項目がある．効果量はブート

                                                69
        ストラップ CI で補助的に確認したが，さらなる反復により不確かさを低減すること
        が望ましい（5.3.3 節）．
   • モデル近似：オフライン評価は滞在比率に基づく合成であり，切替直後の非定常性や
        相関は近似に含まれない．
   • 不確実度較正：確率値が過信されると閾値の意味が崩れるため，較正（温度スケーリ
        ング等）の導入が今後の課題となる（3.2 節）．


6.7 今後の課題
 本研究で未解決の課題として，スキャン挙動の端末差の系統的整理，動的制御における
QoS 指標（TL 分布・Pout ）の高精度評価，およびオンライン学習導入時の安全側設計が挙
げられる．


6.7.1    QoS 評価の高精度化
 動的制御では，イベント時刻の定義と時間同期が結果を左右する．特に長間隔では，開始
位相のずれや受信の間欠性により，TL 分布と Pout (τ ) が不自然に見える場合がある．今後
は，ペイロードにインデックス等を埋め込み，時間軸を確実に復元できるログ設計と解析を
統一する．


6.7.2    行動集合の拡張

 2 値 制 御 は 最 小 構 成 と し て 有 効 で あ る が， 運 用 点 の 探 索 範 囲 を 狭 め る． 今 後 は，
{100, 500, 1000, 2000} のように行動集合を拡張し，制約  の境界に沿ってより良いト
レードオフ点が存在するかを検証する．その際，切替頻度が増えるため，ログ整合と時間同
期の堅牢化が前提条件となる．

おわりに

本研究では，HAR の推論不確実度に基づく BLE アドバタイジング間隔の適応制御を対象
とし，ルールベース方策の定義と評価指標を確立するとともに，提案手法の実機検証を行っ
た．特に，送信・受信・電力計測を統合した計測基盤を整備し，µC/event と受信遅延に基

最適化に接続する基盤を構築した．


本研究のまとめ
 本研究で得られた知見を以下にまとめる．

  • 不確実度と安定度から複合スコア CCS を構成し，閾値・ヒステリシス・最小滞在時
    間を用いたルールベース方策として定義した．
  • 送信（TX），電力（TXSD），受信（RX）の三ノード構成により，同一試行で電力と
    QoS（TL，Pout (τ )）を評価できる基盤を整備した．
  • TL/Pout の算出において，開始位相ずれが結果を歪め得ることを示し，定数オフセッ
    ト補正（v5）として指標定義を固定した．
  • オフライン評価により，固定間隔点と候補方策点のトレードオフを可視化し，実機実
    験の探索空間を縮小する枠組みを示した．
  • 実機実験（D2b/D3）とアブレーション（D4/D4B）により，方策が固定間隔の間の
    運用点として成立し得ることを示し，さらに U が電力（短間隔滞在量）を，CCS が
    同電力で QoS を改善する役割分担が存在することを示唆した．
  • E2 （高干渉）では， CCS は Fixed100 より低電力だが Pout (2s)/TL が悪化した．
    TailGuard 追加により Pout (2s) を 1.28%，T Lp95 を 944.5 ms まで改善し，QoS 制
    約を満たす運用点を確認した（n=6）．


今後の課題
 今後は，動的制御に対して TL 分布と Pout (τ ) を高精度に算出し，オフライン評価の予測
と実測の差分を体系的に説明できる形にまとめる．また，行動集合を拡張し，制約  の境界
